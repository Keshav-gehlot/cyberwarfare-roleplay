# Cyber Warfare 2035 Demo Apps

Three separate detection tools for an M.Tech presentation on "Cyber Warfare 2035: Emerging Trends and the Next Generation of Cyber Threats". Each one runs by itself. They need only Python 3 (no extra packages) and work without internet. Each has a dashboard that opens in a browser.

| Threat | Python | Dashboard |
|---|---|---|
| Post-quantum TLS downgrade | `pq_downgrade_guard.py` | `pq_downgrade_guard.html` |
| False SCADA sensor data | `ics_physics_sentinel.py` | `ics_physics_sentinel.html` |
| Fake satellite radar data | `sar_jitter_analyzer.py` | `sar_jitter_analyzer.html` |

Other files:
- `index.html` is a start page that links the three dashboards in presenting order.
- `01_scenario_briefing.md` is the scenario.
- `03_roleplay_script.docx` is the role-play script with demo cues.
- `04_presentation.pptx` is the slide deck.
- `02_viva_prep.md` has a slide outline, likely questions and a 60-second summary.

## Running

```
python pq_downgrade_guard.py
python ics_physics_sentinel.py
python sar_jitter_analyzer.py
```

Each script prints one normal case and one or more attack cases. To open a dashboard, double-click its `.html` file, or open `index.html` and pick one. In a dashboard, press 1 to 4 to switch scenarios; in the satellite app, Space pauses the stream.

## Demo steps

### pq_downgrade_guard
1. Run the script. The hybrid handshake is approved, and the X25519-only session is terminated and quarantined.
2. In the dashboard, click **Downgrade to X25519**, then **Hybrid label, PQ bytes stripped**. Both are marked critical. The hatched part of the byte bar is the missing 1184-byte ML-KEM share.

### ics_physics_sentinel
1. Run the script. 3000 RPM at 68 °C is nominal. 3150 RPM at 22 °C triggers an interlock trip.
2. In the dashboard, click **Hydra-35 sensor spoof**. Each reading is within its own limit, but the point on the chart falls outside the green area, because a turbine at that speed can't have a 22 °C bearing.

### sar_jitter_analyzer
1. Run the script. The real feed has σ = 0.0965 and is accepted. The fake feed has σ = 0.0035 and is flagged.
2. In the dashboard, click **Deepfake SAR injection**. The trace goes flat and the histogram becomes one bar.
3. Click **Deepfake with injected noise**. The fake feed now passes, which shows the detector's main weakness.

## Limits

- ML-KEM is not broken. The first tool detects ML-KEM being removed from the handshake.
- TLS 1.3 signs the handshake, so that removal needs a TLS-terminating proxy the attacker controls (or a misconfigured endpoint), not just an eavesdropper.
- Attack data is generated by the scripts, not captured from a real network or radio link.
- Thresholds are fixed. A real system would tune them per site and combine several signals.

## Facts used

- X25519MLKEM768 has IANA codepoint 0x11EC. Its client share is 1216 bytes: a 1184-byte ML-KEM-768 encapsulation key (FIPS 203) followed by a 32-byte X25519 key.
- Synchronous speed = 120 × f / p, so a 2-pole generator on India's 50 Hz grid runs at 3000 RPM.
- The IEGC 2023 frequency band is 49.90 to 50.05 Hz. Relay trip settings are wider, so the tool reports out-of-band frequency as an anomaly.
- Modbus/TCP frames have a 7-byte MBAP header followed by the PDU. Values are big-endian IEEE-754 float32.
- Shannon entropy H = −Σ p log₂ p.
